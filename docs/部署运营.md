# 部署与运营

本项目提供单机生产服务：应用、worker、PostgreSQL 和每日备份。生产 Compose 只启动 `app`、`worker`、`db`、`backup`，不包含 Caddy，不占用 80/443，也不申请证书或探测公开域名。HTTPS、域名和证书由你现有的 Nginx、Caddy、宝塔或云负载均衡负责反代。

## 首次部署

准备一台 Ubuntu 22.04/24.04 或 Debian 12/13 服务器，安装入口会在缺少 Docker 时安装 Docker Engine 与 Compose。以 root 执行：

```sh
curl -fsSL https://raw.githubusercontent.com/1075375006/liang-ge-ren/main/ops/install.sh | bash
```

安装入口会克隆项目并调用 `bash scripts/deploy.sh`。首次会自动创建默认配置、生成随机数据库密码、构建镜像、执行迁移并启动 Docker 服务；不会绑定域名、申请证书或占用 80/443。默认文件为安装目录下的 `/opt/liang-ge-ren/production.env`。默认即可启动，只有以下项目按需修改：

- `APP_URL`：可留空；若希望邮件链接直接指向反代地址，可以填写公开 origin。它不用于绑定域名。
- `BIND_ADDRESS` / `APP_PORT`：应用监听地址和端口，默认 `127.0.0.1:33442`。
- 邮件与微信配置在 `/admin` 后台保存，不写入 `production.env`。
- `TRUST_PROXY`：实际反代的可信 IP/CIDR。默认 `loopback,linklocal,uniquelocal` 只适合同机或受控私网；公网或异机反代请改为明确来源，并让代理覆盖客户端传入的 `X-Forwarded-For`、`X-Forwarded-Proto`、`Host`。

首次 `POSTGRES_PASSWORD` 留空即可，脚本会生成随机值并写回配置。已有数据库卷时不得留空，也不得为了更新而修改数据库密码。`COOKIE_SECURE=true` 在生产保留，即使应用只监听本机端口。

如果安装目录被删除后重新克隆，但同一 Compose 项目的数据库容器仍在，部署脚本会从该容器的 Docker 配置中恢复原密码并继续部署；如果数据库容器也已删除，必须从备份的 `production.env` 恢复密码，不能猜测或替换数据库卷。

安装入口会自动执行部署；手动安装或更新时，在安装目录执行：

```sh
cd /opt/liang-ge-ren
bash scripts/deploy.sh
```

`bash scripts/deploy.sh --init` 可单独重新生成缺失配置，但不会覆盖已有文件。配置位置可通过 `DEPLOY_ENV_FILE=/绝对路径/production.env` 指定；状态和备份目录可通过 `DEPLOY_STATE_DIR=/绝对路径` 指定（默认 `.local/production`）。配置文件权限为 600，目录为 700，均被 Git 和 Docker 忽略。

## 反向代理

同机 Nginx 的最小示例（按你的域名和证书路径替换）：

```nginx
server {
    listen 443 ssl http2;
    server_name app.example.com;
    ssl_certificate     /etc/letsencrypt/live/app.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/app.example.com/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:33442;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto https;
        proxy_set_header X-Forwarded-For $remote_addr;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_http_version 1.1;
        proxy_read_timeout 60s;
    }
}
```

代理必须覆盖而不是透传客户端提交的 `Host`、`X-Forwarded-Proto`、`X-Forwarded-For`。应用默认监听 `BIND_ADDRESS=127.0.0.1`、`APP_PORT=33442`。若反代在另一台机器或容器，改成具体内网 IP 或 `0.0.0.0`，只在防火墙中允许该反代来源访问端口，并同步修改 `TRUST_PROXY`。

## 配置字段

根目录 `production.env.example` 是公开模板，首次运行 `scripts/deploy.sh` 会自动复制它并填入随机数据库密码。常用字段如下：

| 字段 | 用途 |
| --- | --- |
| `APP_URL` | 可选公开 origin；来源校验、验证邮件和找回密码链接 |
| `BIND_ADDRESS` / `APP_PORT` | app 监听地址和端口，默认 `127.0.0.1:33442` |
| `COOKIE_SECURE` | 生产固定为 `true` |
| `TRUST_PROXY` | 反代可信来源；只填真实代理地址或受控网段 |
| `POSTGRES_USER` / `POSTGRES_DB` / `POSTGRES_PASSWORD` | 数据库账号、库名和密码；已有卷不得改密码 |
| `SUPPORT_EMAIL` / `OPERATOR_NAME` | 支持联系地址和展示名称；可留空 |
| `REQUIRE_VERIFIED_EMAIL` / `REGISTRATION_OPEN` | 邮箱验证门槛和新注册开关 |
| `/admin` | 管理员初始化、SMTP、微信登录、邮件队列、worker、用户与空间查看 |
| `DEPLOY_ENV_FILE` / `DEPLOY_STATE_DIR` | 配置文件和部署状态目录，可设绝对路径 |

生产 Compose 内部使用 `db:5432` 连接数据库；不要把数据库端口映射到宿主机。应用健康检查、worker 心跳、积分对账和本地 `/api/ready` 检查通过后，脚本才报告成功。若环境文件里显式填写了 SMTP，部署脚本会额外检查连接和 TLS；默认 SMTP 为空时会提示稍后从 `/admin` 配置并继续启动。检查只访问本机端口，不请求 HTTPS，也不要求 DNS、ACME 或公开域名已经可用。

## 更新与维护

更新代码后仍只需：

```sh
cd /opt/liang-ge-ren
bash scripts/deploy.sh
```

脚本使用现有 `production.env`，不以本次 shell 环境变量覆盖已保存值；升级前先备份并执行迁移。失败会保留旧镜像、数据库和配置，不自动改数据库密码。查看服务：

```sh
bash scripts/status.sh
docker compose --env-file production.env -f ops/compose.production.yaml logs --tail=100 app worker db backup
```

手动备份和恢复：

```sh
bash scripts/backup.sh
bash scripts/restore.sh /绝对路径/manual-时间.dump --confirm-replace-database
```

自动备份默认保留至少 14 天。数据库卷不能防止整机损坏；请把备份、`.sha256` 校验文件和生产配置复制到另一台机器或加密对象存储，并定期做独立恢复演练。恢复会覆盖当前数据库，执行前会再次备份；不要对非本项目数据库运行恢复命令。

## 邮件、微信与运营边界

生产默认要求邮箱验证。SMTP 连接检查通过不等于真实邮件送达；开放注册前请用两个真实邮箱完成验证、找回密码、配对、约定验收和心愿兑换，并为发信域配置 SPF、DKIM、DMARC。真实微信授权需要在目标平台登记回调域名，配置见 [北辰微信登录](微信登录接入.md)。

生产配置、真实服务器、DNS、证书、SMTP 收信、反代访问控制以及所在地适用的备案、隐私和经营要求，都必须由运营方在目标环境完成。项目只验证本地 HTTP 服务、容器健康、备份恢复和业务流程，不把本地检查当作公网上线证明。
