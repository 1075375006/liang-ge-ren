多组验收使用独立随机 PostgreSQL 测试库：**20 组情侣、40 个初始账号、2,203 次 Fastify 路由请求、40 封本地 SMTP 验证邮件**。覆盖并发注册、邮箱验证、邀请码唯一性与抢入、配对、任务领取/提交/验收、商品兑换/兑现/确认/退款、多个 worker 调度，以及退出和重新登录。所有空间的任务、计划、商品、订单、个人账本与通知均检查隔离；跨组修改被拒绝，没有负库存、负余额或 5xx，所有钱包与流水一致。

这些数字是本机正确性场景，使用路由注入、真实数据库和本地 SMTP，不是公网吞吐量、可同时在线人数或生产容量承诺。独立测试库在测试结束后按测试规则清理，不接触开发或生产用户数据。

## 重点安全和一致性回归

- 密码恢复采用摘要令牌、有效期和单次消费；响应不暴露邮箱是否注册。重置撤销所有旧会话；修改密码验证当前密码并轮换会话。微信-only 身份不会因补充邮箱而变成密码账号。
- 生产注册要求条款确认并自动发验证邮件，验证前不能创建或加入空间。注册开关可以关闭新账号；已有用户继续登录。
- 安全 Cookie、CSP/HSTS、跨站写请求限制、真实 429、可信代理与伪造 XFF 防绕过均有测试。同网络已登录用户的邮件验证额度相互独立。
- 注销和正常关闭空间共用空间锁：未完成约定取消、计划停止、待兑现订单退款，已兑现结果保留。退出旧空间结算余额到 0，不能把旧积分带给新伴侣；账本保持可对账。
- 特别覆盖了注销与发布任务/计划/心愿、兑换、调度并发；多个 worker 跳过前 50 条锁定计划的边界；通过认证后被暂停的旧请求在账号注销后不能再创建或加入空间。
- 密码重置与旧密码登录的竞争使用数据库锁确定性验证。微信身份、用户、会话锁顺序与注销一致，避免相反顺序死锁或注销后创建会话。
- 配对后必须分别确认第 1 版相处契约；`tests/contract.test.ts` 验证双方均未确认或仅一方确认时任务接口返回 409，双方确认后才可创建任务。真实浏览器也验证契约页会显示“我已阅读并确认”及双方确认状态。
- `/admin` 首次初始化、独立管理员会话、用户与空间概览、暂停用户，以及 SMTP/微信配置加密保存均通过自动化回归；后台接口不回显密钥。
- 生产后台自动创建 `admin` / `admin123456` 默认账号；登录后修改账号密码并用新凭据重新登录通过，当前管理员会话保持有效。
- 新建约定、计划、心愿的表单级 `requestKey` 保证丢失响应后重试不重复创建或发通知；同键改变内容返回 409，跨用户/空间/类型不能互用。旧客户端不带编号仍兼容。
- 所有列表均可游标分页；同秒及微秒时间排序不漏不重。搜索和筛选在服务端执行，游标绑定用户、空间和筛选；单条任务/订单深链接不依赖首批列表。
- 数据库空闲断线会被记录并在后续请求重新连接；事务中的断线明确拒绝而不误报提交。退出流程等待连接池及全部 socket 真正结束，测试再确认 PostgreSQL 后端连接归零后删除独立库，不使用强制断连掩盖泄漏。该边界由 Linux CI 暴露并新增回归覆盖。
- 每日有界维护只清过期会话、授权/安全令牌和到期终态邮件。测试验证外键完整、并发只成功一次、失败回滚、在途邮件保留，业务任务、订单、积分和通知不被清除。

## 真实浏览器

Tabbit 在独立测试后端、真实 PostgreSQL 与本地 SMTP 下完成两个账号的注册、实际验证链接消费、创建/加入空间、抢单、无说明提交、切换另一半验收、心愿上架、积分兑换与取消退款、修改昵称、忘记密码、使用邮件设置新密码并重新登录。

另外验证了关闭空间、导出入口、退出旧空间并结算为 0、建立新空间、注销后自动退出。浏览器长列表使用隔离库的确定性夹具：当前约定从 60 条继续加载到 65 条；连续输入搜索保持焦点，能查到第 220 条历史约定，并通过旧邮件链接直接打开详情。

延迟接口与临时读取故障使用浏览器拦截：离开页面后迟到的深链接不能重新弹出；写入已成功而刷新失败时表单仍关闭，重试只刷新列表，不误导用户重复新建。这些故障注入与数据夹具检查不冒充真实公网故障或真实用户数据。

手机界面保留「约定、心愿、我们」，低频账号、安全、隐私功能按需展开。既有 320–430px 手机与桌面布局检查持续保留；本轮新增账号/恢复/归档流程按手机尺寸操作。首版 [手机截图](screenshots/mobile.png) 与 [桌面截图](screenshots/desktop.png) 仅作历史设计参考，不能作为本次版本截图。六款邮件可查看 [独立预览册](email-preview.html)。

## Docker、备份与恢复

本机 Docker 真正执行了生产构建、两次幂等迁移、应用/worker/每日备份健康检查、非 root 只读应用、数据库和应用不暴露宿主端口。本地 CA 的 HTTPS 通过证书信任校验验证，没有使用跳过 TLS 校验的方式代替证书验证。

容器验收还完成两账号自动验证发信和配对、密码重置、SMTP 连接校验；隔离的明文 Mailpit 在明确关闭 TLS 要求时通过，强制 TLS 时正确拒绝。没有向真实邮箱外发。

备份通过 `pg_dump` 生成归档和 SHA256，恢复前再次备份；恢复后确认备份之后创建的 sentinel 表消失、原有两用户一空间仍在、账本一致。失败路径也验证：恢复先用一次性容器对账，再检查就绪，最后开放入口；对账或就绪失败会实际停止入口与写服务。

独立审查发现并修正了三处部署风险：

1. 恢复失败后仍可能对外运行，现已在失败处理显式停服务，并把对账移到业务启动前。
2. 继承的 `COMPOSE_PROJECT_NAME` 等变量可能污染测试项目，现已强制随机项目、清除配置覆盖、按项目标签核对清场资源；实际 Compose 配置污染断言通过。
3. 常规升级可能在备份前更新 PostgreSQL 镜像，现已固定已有容器的镜像摘要，并禁止常规更新重建数据库；数据库大版本升级属于单独维护流程。

测试恢复过程中附加的 Mailpit 会产生 Compose orphan 提示，它是该隔离测试项目的辅助服务，结束时限定项目清理；真实生产配置不包含它。

## 发布与运营边界

- **已实现且本地验证**：账号恢复与验证、20 组隔离使用、关闭/注销/重新配对、完整分页、数据导出、生产容器、备份恢复、一条命令安装/更新脚本和 GitHub 自动检查配置。
- **仍需目标环境落实**：真实域名与 DNS、80/443 入站、真实公网 ACME 签证书、SMTP 凭据及真实收件箱送达、SPF/DKIM/DMARC、支持邮箱和真实运营主体。安装脚本会检查本机服务；填写环境 SMTP 时也会检查连接，默认未配置 SMTP 会提示从 `/admin` 设置后继续启动，但这些检查不能替代收件箱和业务验收。
- **未在本机执行**：Ubuntu/Debian 的真实 apt 安装、用户实际服务器部署、真实北辰/微信扫码和第三方凭据配置。
- **运营责任**：服务器所在地适用的备案、条款和隐私要求、邮件服务规则、内容投诉处理、容量监测及异地备份。自动备份在同台服务器，不替代异地副本；手工和升级备份不会自动过期删除。恢复后须重新落实已生效的账号注销要求。
- **不在交付范围**：支付/订阅收费、真实货币结算、多机高可用、原生 App、图片上传和离线业务。当前积分不代表现金资产。
